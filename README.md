# scriptshop

A private script catalog. Users log in with a login and password issued by the owner.
One Go binary: no JavaScript, no external resources, no web admin panel.

## How it works

- Passwords: argon2id, generated by the server (130 bits), shown once.
- Sessions: memory only, cookie `__Host-sid` (HttpOnly, Secure, SameSite=Strict),
  30 minutes idle / 12 hours max. Restarting the server logs everyone out.
- Brute force: 5 failures from one IP (IPv6: per /64) → blocked for 1, 2, 4 … 64 min;
  10 failures on one login → blocked for 15 min. An unknown login takes as long to check as a known one.
- CSRF: Origin/Sec-Fetch-Site check (`http.CrossOriginProtection`) + SameSite=Strict.
- Headers: strict CSP, HSTS, no-store, noindex, no framing.
- The server only reads the data. Only the admin CLI writes it (atomically, under a lock).
  Changes are picked up within a second: a disabled user loses their session at once.
- Users can only download scripts they were granted. Files are stored under random names outside any web root.

## Build

```sh
go build -trimpath -ldflags="-s -w" -o scriptshop .
```

Requires Go 1.26+. The binary is static: you can build it on another machine and copy it over.

## Install on a server (Linux + systemd)

```sh
sudo useradd --system --home /var/lib/scriptshop --shell /usr/sbin/nologin scriptshop
sudo install -d -m 700 -o scriptshop -g scriptshop /var/lib/scriptshop
sudo install -m 755 scriptshop /usr/local/bin/scriptshop
sudo cp deploy/scriptshop.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now scriptshop
```

The server listens only on `127.0.0.1:8080`. Expose it through Caddy (automatic TLS):

```sh
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile   # replace example.com with your domain
sudo systemctl reload caddy
```

Login does not work without HTTPS (the cookie is Secure). This is intentional.
The exception is `http://localhost`, for local testing.

Without a domain, pass your own certificate directly:
`scriptshop serve -addr 0.0.0.0:443 -cert cert.pem -key key.pem`
(this needs `AmbientCapabilities=CAP_NET_BIND_SERVICE` in the unit).

Firewall: open only 22 and 443 (and 80 so Caddy can obtain its certificate).

## Administration

Run every command as the service user:

```sh
alias shop='sudo -u scriptshop SCRIPTSHOP_DATA=/var/lib/scriptshop scriptshop'
```

Users:

```sh
shop user add ivan          # prints the password; hand it to the client in person
shop user passwd ivan       # new password; existing sessions end
shop user disable ivan      # revoke access immediately
shop user enable ivan
shop user del ivan
shop user list
```

Scripts (flags go before the file name):

```sh
shop script add -version 1.2 -price '$40' -desc 'Incremental backup.' ./backup.sh
shop script edit 1 -price '$50'
shop script edit 1 -version 1.3 -file ./backup.sh
shop script del 1
shop script list
```

Download access:

```sh
shop grant ivan 1 3         # or: shop grant ivan all
shop revoke ivan 3
```

Users see the whole catalog with prices; granted scripts show `[download]` instead of a price.

## Backup

Copy `/var/lib/scriptshop` (`db.json` + `files/`). Keep the copy just as private.

## Logs

```sh
journalctl -u scriptshop -f
```

Logins, failed attempts, throttling and downloads are logged. Passwords never are.

## Development

```sh
go test ./...                                        # tests: login, sessions, access, throttling
SCRIPTSHOP_DATA=./data ./scriptshop serve            # local: http://localhost:8080
```

| File          | Contents                                     |
|---------------|----------------------------------------------|
| `main.go`     | command dispatch                             |
| `store.go`    | data model, `db.json`, file storage          |
| `server.go`   | server setup, routes, security headers       |
| `handlers.go` | page handlers                                |
| `password.go` | argon2id hashing                             |
| `session.go`  | in-memory sessions                           |
| `limiter.go`  | brute-force protection                       |
| `admin.go`    | admin commands                               |
| `web/`        | templates and CSS (embedded in the binary)   |

The server only reads the data; only the CLI writes it. This is the core rule, so keep it.

For the person running the shop: [docs/managing-users.md](docs/managing-users.md) explains creating and managing users step by step.
